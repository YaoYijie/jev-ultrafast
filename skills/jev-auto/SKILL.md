# jev-auto：把需求整个交出去

`auto_*` 工具和 `ultrafast_*` 工具做的是同一件事的两种分工，选错了会很贵。

| | `auto_*`（本技能） | `ultrafast_*` |
|---|---|---|
| 谁做检查点判断 | 监督模型（便宜） | **你**，每一步都进你的上下文 |
| 你看到什么 | 日志 + 一份报告 | 每一步的决策、置信度、页面 |
| 适合 | "查/比/找"，要翻好几页才能回答 | 一个已知页面上的具体交互、调试、要盯每个选择 |

**默认用 `auto_*`。** 一次 16 步的运行如果走 `ultrafast_*`，十几份 step 报告会塞满你的上下文；走
`auto_*` 烧的是监督模型的上下文，回来只有一份报告。只有当你真的需要看见每一次选择时才降级。

## 用法

```
auto_start(need, url="", mode="standard") → run_id，立刻返回
auto_poll(run_id, since)   → 状态 + 新日志；把上次的 next_line 传回来
auto_result(run_id)        → 报告
auto_list(limit)           → 历史，跨重启
auto_cancel(run_id)        → 下一个检查点停下，仍然出报告
```

**轮询节奏：** 一次运行 90–300 秒。`auto_poll` 间隔 20–30 秒，用 `since=上次的 next_line` 只取新增。
不要密集轮询——除了烧 token 什么都不会更快。

**跑之前先 `auto_list`。** 同一个需求可能已经跑过，`auto_result` 读回来比重跑快得多，也不会再开浏览器。

## 招聘平台前台巡检

只有用户本轮明确要求 Browser use、手动查招聘平台或开始平台巡检时，才使用
`auto_start(need, url="平台起始页", mode="job_patrol")`。这个模式有额外的确定性边界：

- 必须给出 BOSS、前程无忧、猎聘、智联或 LinkedIn 中一个平台的明确 URL；一次运行只固定一个平台；
- 复用用户自己的可见 Chrome 和登录态；如果无法核实为该 profile，预检直接失败；
- 每个检查点最多两步，整轮最多 20 步，动作之间固定等待；招聘平台运行不得并发；
- 投递、沟通、打招呼、收藏、关注、订阅、登录、验证和资料修改一律阻断，不能人工批准继续；
- 新出现验证码、异常 IP／账号、登录墙、401／403／429、明确反爬或跳出当前平台时，停止该平台；
  不换工具、账号、IP、关键词或另一招聘平台补跑。

`platform_stop` 给出停止类别、证据和当时 URL。`platform_blocked` 只表示通道受阻，不能解释成没有岗位。
不要在后台定时雷达中使用这个模式；后台仍只查搜索引擎索引和企业官网。

## need 怎么写

写**整个需求**，不是一步。规划器负责拆段；你替它拆只会拆坏。

- 好：`帮我查 10 月 21 日上海飞东京的直飞航班，列出航司、起降时间、时长、价格，排掉红眼`
- 好：`在这个文档站里找出所有和部署配置相关的页面，给出标题和链接`
- 坏：`点搜索按钮` —— 你已经知道点哪了，整套机器没有用武之地
- 坏：`帮我订最便宜那班` —— 它不会下单，见下

把**约束和想要的输出形状**写进 need（要哪些字段、排除什么、要不要链接）。汇总模型只按 need 写报告。

## 它不会提交任何东西

`auto_start` 启动的运行**没有人在看**，所以门禁遇到提交、下单、支付、登录、注册、申请、发送、删除
这类动作时**直接拒绝并停下这一段**，把它记进报告的 `declined`。

这不是故障，是这个工具存在的前提。因此：

- **永远不要告诉用户"已经帮你订好了/投递了/提交了"。** 它做不到。
- 报告里有 `declined` 时，如实转述："查到了，但停在了『确认下单』这一步。"
- 用户确实要执行提交类动作时，让他们自己跑 `jev-auto-ui`（本地网页，`127.0.0.1:8767`），
  在那里逐个确认。**你没有批准这类动作的接口，这是故意的。**
- 密码、卡号、证件号这类字段**任何模式下都不代填**，也不要建议绕过。

## 读报告

`auto_result(run_id)` 默认**不含页面原文**——十几个页面每页 4000 字会直接塞满上下文。报告不够、
要核对某个结论的出处时才加 `page_text=True`。

报告里的 `trace` 是每个检查点的停止原因。几个容易误读的：

- **`blocked`** 多半是**这一段目标本身做不到**（比如"筛选出非红眼航班"不是一个浏览器动作），
  不是网站不行。不要因此建议换网站。
- **低置信度不等于选错。** 正确选择实测低到 0.42，值得停的在 0.2 附近。
- **`stalled` / `looping`** 才是真卡住：页面没变或同一个选择反复出现。

## 不要自己开浏览器

这套东西的价值就在于 Jev 在**它看得见的元素**里做选择。你一旦自己写脚本，就把它变成了橡皮图章。

禁止：`import jev_ultrafast.browser` / `Agent`、`browser_harness.helpers.cdp`、`Runtime.evaluate`、
`querySelectorAll` / `innerText`、自己拼带查询参数的深链接。要读页面用 `ultrafast_read`，
要换站点用 `ultrafast_navigate`。

## 命令行

同一套东西也有 CLI，适合让用户自己跑：

```bash
jev-auto "查 10 月 21 日上海飞东京的直飞航班，列出航司、时间、时长、价格" --json /tmp/run.json
```

`--no-commit` 强制只读（MCP 启动的运行本来就是这样）；不加时在终端里逐个问。
招聘平台使用 `--job-patrol --url <平台起始页>`；该模式天然只读，不接受提交类动作授权。
`jev-auto-ui` 是网页版，也是**唯一**能批准提交类动作的入口。
