# 岗位巡检验证与运行版本

## 本次修复

- 风控检查覆盖预测前刷新、动作前页面变化，以及 `force` 后的最后一个检查点。只读门禁不能通过省略参数或置信度批准绕过，停止原因保留且不能通过换目标或导航恢复。
- 动作执行后即使观察页面失败，也计入动作预算和限速；保留每个已观察视口的文本、可见链接及实际动作日志。
- OS 文件锁在不同 MCP 进程之间阻止巡检重叠；进程退出自动释放，过期会话在启动检查前回收。
- 浏览器初始化失败、报告生成失败仍清理本任务标签页与锁；规划期间取消不会打开目标页面。
- 已完成任务可从另一个 MCP 进程读取。响应带源码版本，旧进程发现文件更新时拒绝启动并明确要求重新连接。

## 可重复验证

离线回归使用真实 Session、Agent、autopilot 边界，替换浏览器和模型 I/O；跨进程锁使用独立 Python 子进程。测试不访问招聘平台，不调用付费模型。

```bash
uv run pytest
uv run python scripts/check_patrol.py
```

第二条命令要求现有用户 Chrome 已允许 Browser Harness 连接。脚本运行两个真实 stdio MCP 客户端、真实浏览器会话及临时本机 HTTP 站点，仅将模型替换为确定性测试实现。平台白名单只在测试子进程内增加 loopback，生产配置不变。

脚本独立断言：MCP 模式参数、跨进程并发拒绝、实际点击和弹出页接管、中间页面及链接、连续运行、模拟风控后不再输入、预测后风险文本变化拒绝旧动作、规划期间取消、跨进程结果回读、结束后没有测试标签页残留。输出将相关断言合并为 9 项检查。

2026-09-23 本次验证：125 项离线测试全部通过；上述真实 MCP / Chrome 脚本 9 项检查通过；Ruff、两个 JavaScript 语法检查和 `uv build` 通过。没有调用真实模型或访问真实招聘站点。

## 使用前确认

代码更新不会使已有 Python MCP 进程自动加载新版本。重新连接 Jev MCP 后，任意只读调用（例如 `auto_list`）应返回 `runtime.loaded_source_id` 与 `runtime.current_source_id`，两者必须一致。没有 `runtime` 的响应来自加入版本检测之前的实现，也需要重新连接。无需重登招聘账号来加载代码。

## 验证边界

这套检查验证浏览器执行与回收、MCP 集成、信息保留、串行和停止行为，不验证实际模型选择岗位与城市的准确性，也不代表真实招聘平台会允许访问。没有用真实招聘平台做重试验证。真实站点产生新的验证、掉线或异常信号时仍停止当轮平台访问。运行状态 `done` 表示执行结束；判断是否完成需求还要检查 `platform_stop`、`trace` 和实际读取的证据。
